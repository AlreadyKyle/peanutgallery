Status: built. Card: none. Owner: board.

Series position: after studio-reports, before agent-upkeep, built on the merge of studio-reports (the order and each spec's status are in `docs/ROADMAP.md`, "The launch series"). The layout-balance pull request is dropped: home-and-design (#64) shipped `platform/site/e2e/layout-balance.spec.ts` over the kernel `platform/site/scripts/layout-audit.mjs`, and this change makes it card-proof rather than building a second copy. It builds on agent-workflows (the attended role session, typed outputs, `assertPublicTextClean`), agent-system-core (`card_approvals`, `record_card_approval`, the board-session wait) and the supporter loop (the site's `/api/*` documents and their e2e fixtures). ## Problem

No one looks at a visual change before it merges. The gate checks text, types, tests and the build, but never looks at the page or the game (L10). The design checks (axe, sideways scroll, reduced motion, and since #64 layout balance: dead space, stray gaps and unbalanced columns, which the board ruled on 23 September must be caught automatically) live only in the site's own end-to-end suite, which a card can edit, so the check home-and-design's layout passed can be switched off by the next card. Any card may change the tokens, the Card, the brand marks or the route list, and a new page can ship before anyone has seen a design.

## Behaviour

**Board-only design files.** The dispatcher refuses a card whose change touches a path in `design-paths.txt`, before any gate run, as it refuses kernel paths; the gate's kernel guard fails a card branch that does. Because `routes.tsx` is on the list, a new site page is always a board pull request, which the board sees before it merges.

**Card-proof design checks.** The site's design suite (axe WCAG 2.2 AA at 375 and 1440, no sideways scroll, nothing moving under reduced motion, and layout balance on every route) and its fixtures are kernel, so no card can weaken them. One kernel route list, `platform/site/e2e/routes.ts`, feeds `design.spec.ts`, `layout-balance.spec.ts` and `route-shots.spec.ts`; a unit test fails when a path in `routes.tsx` is missing from it. The suite runs in the gate's platform job as today.

**What the gate draws.** A change that touches a render path gets frames, card or board pull request; other changes get none. Render paths: a non-test file under `platform/site/src/`, `platform/site/public/`, `platform/site/index.html`, `platform/site/e2e/`, `seed-1/render/`, `seed-1/e2e/`, `seed-1/index.html` or `seed-1/content/strings.json`. The `frames` job restores the kernel from the base on a card branch, installs without lifecycle scripts, runs no card tests and no card code in Node (the screenshot specs, their configs and every file they import are kernel; a card's code runs only in the browser), and runs the kernel screenshot specs once on the change and once on a worktree of the base:
- Site: every route in `routes.ts`, full page, at 375, 768 and 1440, with reduced motion, on the e2e fixture. A request to any origin other than the local preview fails the run, and a data route that shows its unavailable, stale or loading line instead of the fixture's figures fails the run.
- Game: the canvas at four fixed states (the sim with seed 1 at 0, 600, 3,600 and 21,600 seconds, made by `e2e/frame-states.ts` from the base commit's sim before the change is drawn and read by the spec from that file, saved under the key the game already reads, each advanced 3 seconds on a fixed page clock), and the game page at 375. Nothing on the page tells the game it is being drawn.
The job compares each frame byte for byte with the base's and uploads every frame that differs as a before and after pair, with `changed.txt` listing them, as `design-frames`, kept for one day. The gate fails when the frames job fails.

**The review.** When a card's green gate run has a `design-frames` artifact, the dispatcher downloads it and starts one attended review session, only while a board member is signed in at /board (agent-system-core's board-session wait); a visual card waits at gated until then. The Game Director reviews seed-1 cards and the Platform Director platform/site cards. The session holds the Director's role spec tools, Read, Glob and Grep, and no Bash, Write, Edit, web or MCP tool and no fallback model, in a folder holding the frame pairs and `changed.txt`; its prompt carries the card's intent and acceptance test, the sha the gate passed on and the changed frames' names. It answers with one object: for each of intent, fit, legibility and all_ages, a verdict of pass or revise, the frame it rests on, and a reason code from the schema's closed list. Anything else fails the review, which is retried as an infrastructure stop. The rubric's legibility criterion names dead space, stray gaps and unbalanced columns; the Director is never asked for sizes, spacing or counts, which code measures. The review's model calls are billed to the founder, as every attended role session is, and never to the card.

**Iteration.**
- All pass: the dispatcher records a `visual` approval (approver the Director, maker the builder's session, grader the review session) and merges on the green gate.
- Any revise, with fewer than two rounds used: the round is recorded; the builder revises in a new session on the card's change, in the card's own mode and inside its ceiling, given only the failing criteria, frame names and reason codes; the gate runs again and the Director reviews again.
- Any revise after two rounds: an all-ages revise stops the card through the gate-rejection path, so its unspent money moves exactly as a gate rejection's; any other open criterion merges on the green gate, with the final verdict recorded as the card's visual approval.
- At its ceiling a card pauses and resumes by the rule, as before.
